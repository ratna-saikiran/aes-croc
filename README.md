# aes-croc

The [Croc](https://github.com/pulp-platform/croc) RISC-V SoC from the PULP platform (based on upstream commit `b301ef4`), with an AES-128 encryption accelerator added to its user domain. This is the first block of a smart-meter security SoC: Indian smart meters use DLMS/COSEM, whose security suite is AES-128-GCM.

Croc's own README, describing the SoC, the flow and the tools, is kept as [README_croc.md](README_croc.md).

## What was added

| Path | What it is |
|---|---|
| `rtl/user_domain/aes/aes_core.sv` | Iterative AES-128 encryptor: one round per cycle, 11 cycles per block, keys expanded on the fly |
| `rtl/user_domain/aes/aes_sbox.sv` | S-box lookup table, generated by `gen_sbox.py` from the GF(2^8) definition |
| `rtl/user_domain/aes/aes_obi.sv` | OBI register wrapper |
| `rtl/user_domain/aes/tb/` | Standalone self-checking testbench and test-vector generator |
| `rtl/user_pkg.sv`, `rtl/user_domain.sv` | AES mapped at `0x2000_1000`, its interrupt routed to the core |
| `sw/lib/inc/aes.h`, `sw/lib/src/aes.c` | C driver |
| `sw/test/test_aes.c` | Croc test running the FIPS-197 worked examples |
| `doc/aes/` | Project shortlist and the passing simulation log |

## Register map (base `0x2000_1000`, interrupt 20)

| Offset | Name | Access | Meaning |
|---|---|---|---|
| 0x00 | CTRL | W | bit0 start (ignored while busy) |
| 0x04 | STATUS | R / W1C | bit0 busy, bit1 done (sticky; writing 1 to bit1 clears it) |
| 0x10-0x1C | KEY0-3 | RW | key, bytes little-endian within each word |
| 0x20-0x2C | DIN0-3 | RW | plaintext |
| 0x30-0x3C | DOUT0-3 | R | ciphertext |

## Run it

```sh
# software
make -C sw bin/test/test_aes.hex

# full-SoC simulation (Verilator >= 5.026 and Bender)
cd verilator && ./run_verilator.sh --build --run ../sw/bin/test/test_aes.hex

# standalone core test
cd rtl/user_domain/aes/tb && python3 gen_vectors.py 1000
verilator --binary --timing --top tb_aes_core ../aes_sbox.sv ../aes_core.sv tb_aes_core.sv && ./obj_dir/Vtb_aes_core
```

Toolchain notes: the Ubuntu 24.04 Verilator package (5.020) cannot build Croc's `tc_sram.sv`; 5.038 works. Debian's `gcc-riscv64-unknown-elf` has no rv32 `libm` and relaxes `la sp` against an uninitialised gp. With it, drop `-lm` and link with `-Wl,--no-relax`, or use Croc's Docker image.
